---
title: 认证
description: API Key 的两种提交方式、优先级与失败信封。
---

所有受保护的 `/v1` 接口共用同一套凭据提取规则。

## 提交方式

| 方式 | 请求头 | 惯例来源 |
| --- | --- | --- |
| 方式一 | `x-api-key: <UNIO_API_KEY>` | Anthropic 协议 |
| 方式二 | `Authorization: Bearer <UNIO_API_KEY>` | OpenAI 协议 |

两种方式在**任意入口协议**下都被接受：OpenAI 入口也接受 `x-api-key`，
Messages 入口也接受 Bearer。两个头同时存在时，**`x-api-key` 优先**。

`Authorization` 头的 `Bearer` 前缀大小写敏感。

## 认证失败

缺失、无效、已撤销、禁用或过期的密钥在进入协议处理前被统一拒绝，返回 `401`。
当前无论入口协议，认证失败均使用 OpenAI 通用错误信封：

```json
{
  "error": {
    "message": "...",
    "type": "...",
    "param": null,
    "code": "..."
  }
}
```

注意：`/v1/messages` 的认证失败目前也是上述形状，而非 Anthropic 原生错误信封。

## 请求标识

每个响应都携带 `X-Request-ID` 头，值为本次请求的追踪标识：

- 客户端可以主动发送 `X-Request-ID`（不超过 128 个字符，仅含 ASCII 字母、数字与 `. _ - :`），
  平台会原样采用并贯穿本次请求的全部日志；
- 缺失或不合规时由平台生成替代值。

排障与工单沟通时请附上该值。
