---
title: 选择协议
description: OpenAI-compatible 与 Anthropic-compatible 的适用场景与边界。
---

UnioAPI 以协议原生形式提供服务：你选择哪种协议，就使用该协议的请求、响应、流式事件与错误信封。
平台不会把一个协议的公开形状转换为另一个协议。

## 端点总览

| 协议族 | 端点 | 用途 |
| --- | --- | --- |
| OpenAI-compatible | `POST /v1/chat/completions` | 对话补全，支持非流式与 SSE |
| OpenAI-compatible | `POST /v1/responses` | Responses 主操作，支持非流式与 SSE |
| OpenAI-compatible | `GET /v1/models` | 列出可调用模型与能力标签 |
| Anthropic-compatible | `POST /v1/messages` | 消息生成，支持非流式与命名 SSE 事件 |

## 怎么选

- **沿用 OpenAI SDK 或 OpenAI 兼容工具**（Codex、Cursor、TRAE、OpenCode 等）：选
  OpenAI-compatible，基础地址填 `https://api.unioapi.com/v1`。
- **沿用 Anthropic SDK 或 Claude Code**：选 Anthropic-compatible，基础地址填
  `https://api.unioapi.com`，请求需携带 `anthropic-version` 头。
- 同一把 API Key 在两种协议下通用；模型能否用某个协议调用，取决于该模型当前可用渠道的协议集合，
  见 [GET /v1/models](/docs/api/models) 的 `protocols` 字段。

## 边界说明

- 品牌名称仅用于指明兼容的协议族，不代表官方合作、背书或上游供应商列表。
- 依赖服务端状态的 Responses 操作（查询、删除、取消等）不在服务范围内，返回 `501`；
  详见 [POST /v1/responses](/docs/api/responses)。
